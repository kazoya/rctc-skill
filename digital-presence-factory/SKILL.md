# Digital Presence Factory (Concept Factory)

**Invoke:** `/digital-presence-factory` · `/dpf` · `/concept-factory`

## What this is
A **thin orchestrator + recipes**, not a giant skill.
The value extracted from `factory-sales-concept` and Suhib AI Delivery Portfolio is the **method**:

`discover → inspect → reason → design → build → verify → package → publish`

## Hard rules
1. Project1 (`C:\\project1`) and Master (`C:\\master`) stay first-class proving grounds — do not weaken Dry Run / buyHalt / approval gates to demo RCTC.
2. Never invent numbers, clients, certificates, or live URLs.
3. Prefer **Reuse → Compose → Extend → Generate New** (skill-factory only after composition fails).
4. Dogfood: any new sub-skill goes Draft → Validate → Review → Test → Package → **Owner approval** → Publish. Never Generate → auto-trust → auto-publish.
5. Community evidence may feed recipes (Question → Answer → Reproduction → Recipe → Candidate Skill) but **GitHub is source of truth**.

## Minimal input → recipe picker
Accept any of: person name, company URL, GitHub profile, factory URL, project folder, short business description, existing repo.

Then choose a recipe from `digital-presence-factory/recipes/`:
- `personal-engineering-portfolio`
- `technical-delivery-portfolio` (Suhib AI Delivery DNA)
- `factory-sales-concept`
- `company-marketing-site`
- `product-showcase`
- `project-evidence-portal`

## Pipeline (every recipe)
| Stage | Do | Compose with |
|---|---|---|
| discover | Collect evidence paths/URLs; list unknowns | RCTC method / Start Skill |
| inspect | Read public site / folder / GitHub; no invention | browser or local read |
| reason | Pick recipe + constraints + human gates | focused3 THINK |
| design | Information architecture + honesty labels | recipe notes |
| build | Implement in target folder only | web-marketing / factory-sales-concept |
| verify | build/lint/tests/verify script as recipe requires | safe-forward-execution |
| package | zip or consult pack if needed | update-zip-skill |
| publish | GitHub/Vercel only with owner gate | owner approval |

## Proving grounds checklist
Before/after meaningful DPF changes that touch shared tooling:
- [ ] Project1 typecheck (or verify) still green; buyHalt/Dry Run unchanged
- [ ] Master still reachable; no destructive rewrite of roles without ask
- [ ] Portfolio DNA preserved: single data source, no invented metrics
