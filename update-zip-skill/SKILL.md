# مهارة التطوير والضغط

دورة مغلقة من أربع مراحل:

```
حصاد الأرقام  →  ضغط الحقائق  →  استشارة خارجية  →  تطبيق التحسينات
   harvest          pack             consult             ingest
```

## ملفات التعريف / Profiles

| الملف | ماذا يحصد | ماذا يضغط | ماذا يستوعب |
|---|---|---|---|
| `risha360-social` (الافتراضي) | مشاهدات ومتابعون وحالات نشر من المنصات وقاعدة social-autopilot | موجز + قيود العلامة + عيّنة تصاميم | `04-schedule.json` آليًا؛ النصوص إلى `review/` |
| `portfolio-site` | HTTP لكل رابط منشور، Lighthouse، axe، آخر Playwright، سلامة الأصول، Git | موجز + قيود المحفظة + BRAIN.md + docs + الكود بلا node_modules | ملفات الكود إلى **فرع مراجعة** ثم `npm run verify`؛ `data/` و`OUT/` تُحجز للمراجعة ولا تُطبَّق |
| `web-project` | أي مستودع له package.json: Git، مسارات `app/`، نتائج verify/build/test من السجلات، axe، سجل الادعاءات في `data/site.ts` إن وُجد | موجز + قيود صدق عامة + ASK بقالب RCTC + docs + لقطات + `source/` بلا node_modules + بصمة SHA-256 | **مراجعة فقط**: `review/<stamp>/DIFF-REPORT.md` بفرق كل ملف ونسخ المتغيرات؛ لا فرع ولا كتابة في المشروع؛ الدمج قرار المالك بعد `npm run verify` |

الاختيار: `--profile portfolio-site` أو `UZ_PROFILE=portfolio-site`. المشروع الهدف: المجلد الحالي أو `--root <dir>`.

```bash
cd C:/Suhib-AI-Delivery-Portfolio
node C:/rctc-skill/update-zip-skill/bin/uz.js cycle  --profile portfolio-site                 # حصاد + حزمة استشارة
node C:/rctc-skill/update-zip-skill/bin/uz.js ingest <IMPROVE.zip> --profile portfolio-site   # فرع مراجعة + verify، لا دمج

cd C:/World_Cup_Fintech_Festival
node C:/rctc-skill/update-zip-skill/bin/uz.js cycle  --profile web-project                    # حصاد + حزمة استشارة (أي مشروع)
node C:/rctc-skill/update-zip-skill/bin/uz.js ingest <improved.zip> --profile web-project     # تقرير فرق في review/ فقط
```

**مثال موثّق (`web-project`, 2026-09-17):** حزمة World Cup Fintech Festival أُرسلت لوكيل خارجي؛ عاد بـ 30 سؤال
لجنة وشريحة أثر مالي ووضع لجنة؛ `ingest` أنتج تقرير الفرق؛ روجعت الادعاءات ضد وثائق المنتج فصُحّحت إجابتان
كانتا تصفان سلوكاً غير مبني (FX)؛ ثم `npm run verify` أخضر قبل الدمج. **الدرس:** الوكيل الخارجي يبالغ أحياناً
في وصف ما هو «مبني»؛ كل ادعاء يُعاد التحقق منه ضد مصادر المشروع قبل الدمج.

قاعدة الاستيعاب في `portfolio-site`: **الردّ مسودّة لا أمر.** لا يُكتب في `main`، لا يُنشر، ولا يُطبَّق أي تغيير على محتوى المالك؛ الدمج قرار المالك بعد بوابات خضراء.

## المبدأ الحاكم: حقائق لا انطباعات

الحزمة المُرسَلة تحمل **أرقامًا مقيسة**: كم مشاهدة لكل منشور، في أي ساعة نُشر، أي كابشن،
أي تصميم، وأي المنصات فشلت ولماذا. لا تُرسل «نظن أن التفاعل ضعيف» — تُرسل الجدول.

> مستشارٌ يقرأ أرقامًا يعطي قرارًا. ومستشارٌ يقرأ انطباعات يعطي كلامًا عامًا يصلح لأي مشروع
> على الأرض — وهو بالضبط ما لا ينفعنا.

ولذلك **الحصاد مرحلة أولى مستقلّة**: بلا أرقام تفاعل حقيقية تتوقف الدورة وتقول لماذا،
بدل أن تُرسل حزمة جوفاء وتعود بنصائح مكرّرة.

## القواعد التي **يجب** أن تُرسل مع الحزمة

المستشار الخارجي لا يعرف قيود العلامة، فيقترح ما يخالفها. لذلك تحمل الحزمة ملف
`CONSTRAINTS.md` يذكر صراحةً:

- **اللهجة:** سعودية رزينة — لا فصحى إذاعية، ولا لغة قانونية ثقيلة، ولا لهجة سوقية.
- **التشكيل:** النصّ العربي الذي ينطقه محرّك الصوت يُكتب **بالتشكيل**.
- **لا موسيقى خلفية** في الفيديوهات — تعليق صوتي فقط.
- **لا قرآن ولا نشيد وطني** خلفيةً إطلاقًا، ولا أي صوت لا يطابق معنى الكلام فوقه.
- **البريد مجمَّد** حتى تُستعاد سجلات النطاق — فلا تُقترح حملات بريدية.
- **أولوية النشر:** تيك توك وإنستقرام.
- الهوية: بنفسجي عميق · أسود · ذهبي دافئ · كريمي. وشعار واحد بلا علامات مائية غريبة.

بلا هذا الملف تعود الحزمة بتوصيات تخالف العلامة، فتُهدر الدورة كلها.

## الوضعان

**`send`** — الإرسال المباشر عبر جسر ChatGPT في المتصفّح: يرفع الملف المضغوط، يكتب الطلب،
ينتظر الردّ، ويحفظه. يحتاج جلسة ChatGPT مفتوحة في بروفايل العمل.

**`pack`** — يجهّز الملف فقط، ويطبع مساره ونصّ الطلب ليرسله المالك بنفسه. **هذا الوضع
الافتراضي**: لا يعتمد على تبويب متصفّح ولا على حصّة، ويعمل دائمًا.

## ما تتوقّعه في الردّ

تُطلب حزمة تحسين بملفات مفصولة كي تُطبَّق آليًا لا يدويًا:

```
IMPROVE/
  01-hooks.md              خطّافات الثواني الثلاث الأولى — بدائل مكتوبة جاهزة
  02-captions.md           قوالب كابشن لكل منصة بحدودها
  03-video-spec.md         تعديلات على مواصفة الفيديو (مدة، إيقاع، نصّ الشاشة)
  04-schedule.json         أوقات النشر المقترحة لكل منصة مع سبب كل وقت
  05-prompts.md            تحسينات برومبت توليد التصاميم والنصوص
  06-experiments.md        تجارب A/B مقترحة بفرضية وقياس لكل واحدة
  07-diagnosis.md          تشخيص ضعف التفاعل مستندًا إلى أرقامنا
```

`04-schedule.json` وحده قابل للتطبيق الآلي المباشر على `platform_configs.peak_windows`.
البقية تُراجَع بشريًا قبل الاعتماد.

## الاستدعاء

```bash
node bin/uz.js harvest      # يحصد أرقام التفاعل الحيّة (متصفّح)
node bin/uz.js pack         # يجمع ويضغط ويطبع الطلب
node bin/uz.js send         # يضغط ويرسل عبر جسر ChatGPT
node bin/uz.js ingest <zip> # يطبّق حزمة التحسين العائدة
node bin/uz.js cycle        # harvest ثم pack في أمر واحد
```

## حدود يجب ذكرها للمالك

- **الحصاد يحتاج جلسات مسجَّلة** في بروفايل العمل. المنصة غير المسجَّلة تُبلَّغ ولا تُتخطّى بصمت.
- **إنستقرام وفيسبوك يخفيان المشاهدات** لغير مالك المنشور؛ نقرأ ما يُعرض فقط ونقول ما نقصنا.
- **الردّ مسودّة لا أمر.** لا تُطبَّق توصية تخالف `CONSTRAINTS.md` ولو جاءت مقنعة.
