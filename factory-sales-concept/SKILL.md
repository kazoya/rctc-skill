# factory-sales-concept

**اسم الاستدعاء:** `/factory-sales-concept`

مهارة إنتاج. لا تبدأ البناء حتى يكتمل موجز الاستقبال (أو يصرّح المستخدم بالمضي بالافتراضات).
بعد الفحص: اصنع المنصة، مستودع GitHub، وبناء Vercel.

المراجع الحية (انسخ الأسلوب منها، لا المنتج):

- `C:\almajjarra` — أسمدة / ري / قرار بشري على الصمام
- `C:\Factories\Banoon` — أطفال / مسابقة مدارس / قرار بشري على الجائزة

التفاصيل: [prompt-template.md](prompt-template.md) · [reference.md](reference.md)

## 1) موجز الاستقبال — اجمع ثم اسأل ثم ابنِ

اقرأ رسالة المستخدم واملأ الجدول. **لا تخترع** هاتفاً أو بريداً أو شهادة.

| الحقل | مصدر مقبول | إن نقص |
|--------|-------------|--------|
| عنوان المنصة / اسم العلامة | عنوان صفحة الويب أو المستخدم | اسأل |
| رابط الموقع | المستخدم (مطلوب) | اسأل فوراً — بدونه لا فحص |
| مجلد المشروع | المستخدم، وإلا `C:\Factories\{slug}` | أكّد المسار قبل الإنشاء |
| الشركة الأم / المصنع | المستخدم أو «من نحن» | اسأل إن لم يظهر |
| واتساب المبيعات | المستخدم، ثم ملف إكسل إن أشار إليه، ثم صفحة الاتصال | اسأل |
| بريد المبيعات | المستخدم، وإلا `sales@` أو `info@` نطاق الموقع إن وُجد فعلاً | اسأل إن صفحة الاتصال بلا بريد |
| هاتف إضافي | المستخدم أو الموقع | اسأل إن لم يوجد أي رقم |
| ما يميّز المنتج/الخدمة | كلام المستخدم حرفياً (مسابقة، بلا مواد حافظة، …) | اسأل: «ما الجملة التي يجب أن تسمعها المديرة/المهندس في أول عشر ثوانٍ؟» |
| جمهور الإغلاق | افتراض: مدير المبيعات | غيّر إن حدّد المستخدم مديراً آخر |

اسأل عن **الناقص عالي الأثر دفعة واحدة** (قائمة قصيرة)، لا سبعة أسئلة متسلسلة. إن قال «تجاهل»، صرّح بالافتراض وامضِ.

بعد وجود الرابط: افحص الموقع **فوراً** ولو بقي حقل ناقص — الموقع غالباً يملأ الهاتف والعنوان والمنتجات.

## 2) فحص الموقع

افتح الصفحة الرئيسية وAbout وProducts وContact (وكل تصنيف ظاهر). سجّل:

- ما هو منشور بوضوح (منتجات، عنوان، هواتف، شهادات مذكورة)
- ما هو مكسور أو رقيق (إحصاءات صفر، نصوص مكررة، نموذج فارغ، لغة واحدة، أخطاء إملائية)
- فرص الأتمتة الواقعية (واتساب = دفتر طلبات، لا بوابة موزّعين، لا قناة مدارس/حقل/…)
- **لا تختلق** طاقة إنتاج أو دول تصدير أو جوائز عالمية إن كانت الصفحة تعرض `0` أو «Coming Soon»

## 3) البناء — نفس أسلوب المجرة / بنون

1. أنشئ المجلد إن لم يوجد. اعمل داخل مسار المشروع (لا تخلط مع مصنع آخر).
2. انسخ الهيكل التقني من أقرب مرجع (`almajjarra` أو `Banoon`): Next.js 16، RTL، خط عربي محلي، shadcn، QR واتساب، شارة Demo، Human-in-the-loop.
3. **لون وهوية** من شعار/موقع المصنع — لا تُبقِ أخضر الزراعة على مصنع شوكولاتة.
4. الصفحة الرئيسية تُقنع مدير المبيعات بالاتصال في نفس اليوم. CTA واتساب + هاتف في شريط واضح.
5. صمّم **محرّك تفاعلي واحد** يناسب العمل (ري للمجرة، مسابقة لبنون، ما يعادل تمييز المنتج هنا) — الاقتراح يظهر، **التنفيذ لا يتم إلا باعتماد بشري**.
6. اكتب ما يميّز المنتج بعبارة المستخدم. إن كان ادعاءً غذائياً/قانونياً: يظهر في المنصة مع ملاحظة أنه يحتاج اعتماد جودة قبل الطباعة.
7. أعلن في التذييل: هذا تصور مستقل للعرض، ليس نظاماً رسمياً للشركة.
8. `npm install` ثم `npm run build` حتى ينجح.

صفحات حد أدنى (عربي): رئيسية، تصور تنفيذي، كتالوج من الموقع، اختناقات ظاهرة، أتمتة، CRM/طلبات، مسابقة أو المحرّك الخاص، رسائل مبيعات، تقييم اكتشاف، تواصل، لوحة تجريبية، ROI توضيحي، خطة تنفيذ.

## 4) GitHub ثم Vercel

بعد نجاح البناء:

1. `git init -b main` إن لزم، التزم الملفات (بلا `.env` ولا أسرار).
2. `gh repo create {Name} --source=. --remote=origin --push --public` تحت حساب `kazoya`، بنفس أسلوب `AlMajjarra` و `Banoon`.
3. اربط فيرسيل بفريق **muqasa** (`team_33SV2q7GqfsqIuQ9eJ9jfE1b`) عبر `create_git_project`، الاسم بحروف صغيرة، وانتظر `READY`.
4. أعد للمستخدم: مسار المجلد، رابط GitHub، رابط الإنتاج، وما يزال «غير معروف».

## 5) قيود صدق

- أرقام العمليات تجريبية وموسومة.
- الصفحات الرقيقة تُعلن رقيقة — لا تُلفَّق نشرة صنف.
- السعر، الجائزة، فتح صمام، وادعاء المكوّنات: اعتماد بشري.
- مطوّر QR الافتراضي إن وُجد في المرجع: `م. صهيب الصالح` / `962787523192` — لا تغيّره إلا إذا طلب المستخدم.

## 6) بعد التسليم

قل للمستخدم يفتح مجلد المشروع في Cursor لتكملة الاكتشاف (قائمة عملاء حقيقية، شهادات، أسعار).
